Built

01

Idea

A need becomes a clear intent, grounded in the Director’s recorded words and the architecture.

Working practice

Personal advisor

Reads the work, checks claims and advises the Director. Does not direct the supervisor.

Working practice

Library lane

Ordinary CES documents go straight to main under an agent’s identity. Protected rules and code use the controlled lane.

Built

02

Packet

The docket opens a bounded piece of work: intent, owner, scope, dependencies and a clear stopping point.

Partly built / incomplete

Estate supervisor

Owns the docket and the delivery loop: briefs builders, judges evidence, arranges reviews, merges and authorized deploys.

Partly built / incomplete

Laboratory Mode

Director-declared labs explore freely; outside agents bring peer evidence. A chosen result enters the docket before product promotion.

Working practice

03

Plan

A written plan precedes building. A reviewer from another model family checks it against the intent and evidence.

Partly built / incomplete

Brief & dispatch

A named builder receives the task, sources, proof owed and stop lines. The dispatch is closed when its work is done.

Partly built / incomplete

Controlled lane

Code, shared contracts and operational rules follow the packet, branch and pull-request route. CES’s remaining engine code only shrinks.

Partly built / incomplete

04

Build

The launcher opens an isolated worktree and branch. A builder implements and tests the plan, then opens a pull request.

Built

Builders & identity

Bounded builders do the work; identity names the editor, with the model recorded separately. The harness enforces their limits.

Partly built / incomplete

Contract-CI

Cheap checks run first; review effort follows risk. Sensitive changes receive deeper scrutiny, with evidence attached to the change.

Partly built / incomplete

05

Review

Tests and a reviewer from a different model family check the whole final change. Real defects return to the builder; changed code is reviewed again.

Partly built / incomplete

What holds the work

Tests, sound independent review and resolved serious findings guard merge. Only real product or authority questions go to the Director.

Partly built / incomplete

The CTO’s own work

A separate lane builds the foundation. Agents read its contracts and route questions through the Director; they do not write to the CTO’s branches.

Working practice

06

Merge

The supervisor checks the final version and merge authority, then lands the change. A merge that deploys waits for the Director.

Working practice

Production pins

A deploying product selects a reviewed engine version. Landing engine code alone does not move the running platform.

Built

Protect before release

Back up affected data, preserve a recovery path, keep secrets out of records and test real infrastructure where the claim depends on it.

Partly built / incomplete

07

Deploy

With the Director’s word and the backup in place, the delivery workflow releases the chosen version and checks the running service.

Partly built / incomplete

Where it runs

Managed cloud, the person’s own workstation, or an organisation’s appliance use the documented delivery model. The Mini is not a product dependency.

Direction · not built

Harvest the practice

Reports preserve what worked and what failed. Lessons become component changes only when the evidence changes a component or its contract.

Working practice

Close

Sources, evidence and reading limits
  • This is a documentary snapshot, not a fresh audit of deployed services or live branch protection. Built means the cited mechanism exists, not that the complete delivery path is proven.
  • When complete expresses documented design in the present tense. Developer Room and topology proposals remain proposals; no future implementation, cutover or authority is invented.
  • The 24–25 September merge records supersede older descriptions of panel-driven merge authority in STACK. The panel remains advice until the rewrite; the desired required independent-review check is a separate mechanism.
  • The Developer practice folder contradicts STACK’s older claim that its harvest is absent. Its inventory and mock are included, with their experimental status preserved.
  • The advisor is shown as counsel to the Director, as requested. Earlier handoffs permit reminders and steering; they do not establish an enforced no-command boundary.
